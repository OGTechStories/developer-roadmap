# OGTechStories

OGTechStories is a technology learning library built with [Docusaurus](https://docusaurus.io/).

The site currently has two documentation collections:

- `docs/Roadmaps/` for learning roadmaps.
- `docs/Interview-Questions/` for interview preparation.

Both collections use automatically generated sidebars. In most cases, adding a correctly named Markdown file in the correct folder is enough to make it appear in the site navigation.

## Project Setup

The project uses Node.js `24.14.0`. The required version is recorded in `.nvmrc`.

```bash
npm install
npm run start
```

The development site opens at `http://localhost:3000`.

## Documentation Structure

Use this structure when adding content:

```text
docs/
├── Roadmaps/
│   ├── introduction.md
│   ├── foundations/
│   │   └── computer-fundamentals/
│   │       └── introduction.md
│   └── programming/
│       └── python-basics/
│           └── introduction.md
└── Interview-Questions/
    ├── Python/
    │   ├── introduction.md
    │   └── fundamentals.md
    └── JavaScript/
        └── introduction.md
```

Use one roadmap folder per technology, subject, or programming language. The current roadmap is Python, so its sections live directly under `docs/Roadmaps/`; there is no extra `Python` container folder.

Examples:

```text
docs/Roadmaps/JavaScript/introduction.md
docs/Roadmaps/Databases/SQL/introduction.md
docs/Interview-Questions/JavaScript/introduction.md
docs/Interview-Questions/Databases/SQL/introduction.md
```

Use consistent folder names. `JavaScript` and `javascript` can become different paths on case-sensitive hosting systems.

## Creating A New Roadmap

1. Create a technology or roadmap folder under `docs/Roadmaps/`.
2. Add an `introduction.md` file as the first page.
3. Add more Markdown files for individual topics.
4. Set `sidebar_position` so the pages appear in the intended order.

Example: `docs/Roadmaps/JavaScript/introduction.md`

```md
---
sidebar_position: 1
title: JavaScript Roadmap
description: A practical path from JavaScript fundamentals to advanced concepts.
---

# JavaScript Roadmap

Write a short introduction to the technology and explain what this roadmap covers.

## Learning order

1. Syntax and variables
2. Functions and scope
3. Objects and arrays
4. Asynchronous JavaScript

Continue with the next topic when you are ready.
```

The page will be available at:

```text
/docs/Roadmaps/JavaScript/introduction
```

## Creating Interview Questions

1. Create the matching technology folder under `docs/Interview-Questions/`.
2. Add an `introduction.md` overview page.
3. Add topic pages such as `fundamentals.md`, `oop.md`, or `system-design.md`.
4. Put one question under a clear heading and follow it with a concise answer.

Example: `docs/Interview-Questions/JavaScript/fundamentals.md`

````md
---
sidebar_position: 2
title: JavaScript Fundamentals Interview Questions
---

# JavaScript Fundamentals Interview Questions

## What is the difference between `let`, `const`, and `var`?

Explain the difference directly. Include a short code example when it improves understanding.

```js
const language = 'JavaScript';
```

## What is a closure?

Add the answer here, followed by a practical example or an important edge case.
````

The page will be available at:

```text
/docs/Interview-Questions/JavaScript/fundamentals
```

## Front Matter

Front matter goes between the first pair of `---` lines at the top of every Markdown file.

Common options:

```md
---
id: custom-page-id
title: Page title shown in the browser and sidebar
sidebar_label: Short sidebar label
sidebar_position: 2
description: Short search-engine and page description.
slug: /custom-url
hide_title: false
toc_min_heading_level: 2
toc_max_heading_level: 3
---
```

Use these options as follows:

- `sidebar_position`: controls the order in the generated sidebar. Lower numbers appear first.
- `title`: changes the document title without changing the filename.
- `sidebar_label`: uses a shorter name in the sidebar.
- `description`: describes the page for search and metadata.
- `slug`: changes the URL. Use it only when a stable custom URL is important.
- `id`: gives the page a stable Docusaurus document ID. Usually the filename is enough.
- `toc_min_heading_level` and `toc_max_heading_level`: control which headings appear in the right-side table of contents.
- `hide_title`: hides the automatically rendered page title. Avoid it unless the page has its own title layout.

For normal pages, use only `sidebar_position`, `title`, and `description` when they are useful.

## Sidebar Organization

The sidebar configuration is in [`sidebars.js`](sidebars.js):

```js
const sidebars = {
  roadmapSidebar: [{type: 'autogenerated', dirName: 'Roadmaps'}],
  interviewSidebar: [{type: 'autogenerated', dirName: 'Interview-Questions'}],
};
```

Because the sidebars are autogenerated:

- New files under `docs/Roadmaps/` appear in the Roadmaps menu.
- New files under `docs/Interview-Questions/` appear in the Interview Questions menu.
- `sidebar_position` controls page order.
- Folders become sidebar categories automatically.
- You do not need to edit `sidebars.js` for normal new pages.

Category breadcrumbs are clickable only when the category has a `link`. The current page is shown as the final breadcrumb and is intentionally not a link. Use `link.type: "generated-index"` for a section overview or `link.type: "doc"` for a category that should open a specific document.

When a topic is stored as a folder containing `introduction.md`, add `_category_.json` inside that topic folder to control its order. Otherwise, Docusaurus may display topic folders alphabetically.

For example, for the Foundations section:

```text
docs/Roadmaps/foundations/
├── computer-fundamentals/
│   ├── _category_.json   # position: 1
│   └── introduction.md
├── linux-command-line/
│   ├── _category_.json   # position: 2
│   └── introduction.md
├── bash-scripting/
│   ├── _category_.json   # position: 3
│   └── introduction.md
└── git-github/
  ├── _category_.json   # position: 4
  └── introduction.md
```

### Naming A Category

Add `_category_.json` inside a folder when the generated category needs a specific label or order:

```json
{
  "label": "JavaScript",
  "position": 2,
  "link": {
    "type": "generated-index",
    "title": "JavaScript Roadmap",
    "description": "A structured path for learning JavaScript."
  }
}
```

The `link` block is optional. Without it, the category is simply expandable in the sidebar.

## Headings And Page Layout

Use one `#` heading for the page title. Docusaurus can render the title from front matter, so do not create multiple top-level headings.

Use headings in order:

```md
# Page title

Short introduction.

## Main topic

Explanation.

### Detailed point

Example or edge case.
```

Good documentation pages usually follow this pattern:

1. Explain the concept in plain language.
2. Show a small example.
3. Mention common mistakes or edge cases.
4. Link to the next related topic when useful.

Do not skip from `##` to `####`. Use headings to describe the content structure, not only to make text larger.

## Links Between Documents

Use relative Markdown links for links between nearby documents:

```md
Read the [Python fundamentals](./fundamentals.md) next.
```

Use site paths when linking to a document from a different collection or a homepage component:

```md
See the [Python interview questions](/docs/Interview-Questions/Python/introduction).
```

Useful link rules:

- Use the real filename and folder casing.
- Do not include `.md` in a Docusaurus site URL.
- Prefer internal links over hard-coded external URLs.
- Use descriptive link text such as `Python fundamentals`, not `click here`.
- Check every link after moving or renaming a document.

## Next And Previous Links

Docusaurus automatically creates next and previous links for documents in the same sidebar sequence.

To control the sequence, use `sidebar_position`:

```md
---
sidebar_position: 1
---
```

The next and previous links follow the generated sidebar order, including category order. They do not follow filename order reliably.

To hide the table of contents on an individual page:

```md
---
hide_table_of_contents: true
hide_title: false
---
```

Do not hide navigation on normal learning pages. A clear sequence is one of the main benefits of the roadmap structure.

## Markdown Features

### Lists

```md
- First item
- Second item

1. First step
2. Second step
```

### Code Blocks

Always include the language when a code block has one:

````md
```python
def greet(name):
    return f"Hello, {name}"
```
````

Supported highlighted languages configured for this site include Python, Bash, JSON, YAML, Markdown, and SQL. Common languages such as JavaScript can also be used with their standard fence name.

### Notes And Warnings

Use Docusaurus admonitions for important supporting information:

```md
:::tip
Use this approach when you want a short practical recommendation.
:::

:::warning
Call out a common mistake or behavior that may surprise the reader.
:::

:::info
Add useful context without interrupting the main explanation.
:::
```

### Tables

```md
| Concept | Meaning |
| --- | --- |
| `==` | Compares values |
| `is` | Compares object identity |
```

Keep tables small enough to remain readable on mobile screens.

## Writing Standards

- Use clear, direct language.
- Keep one main concept per page or section.
- Use sentence case for headings.
- Explain acronyms the first time they appear.
- Prefer practical examples over long introductions.
- Keep interview answers concise, then add depth with examples or edge cases.
- Do not add placeholder pages, fake links, or unfinished sections to the live navigation.
- Keep roadmap pages and interview pages separate, even when they cover the same technology.
- Use ASCII filenames and lowercase filenames for topic pages when possible, for example `data-structures.md`.

## Local Validation

Start the development server while writing:

```bash
npm run start
```

Before committing new documentation, run a production build. The configuration uses `onBrokenLinks: 'throw'`, so broken internal links and invalid routes should fail the build:

```bash
npm run build
```

Preview the generated site with:

```bash
npm run serve
```

Check the following manually:

- The new page appears in the expected sidebar.
- The page title and headings are correct.
- Next and previous links follow the intended order.
- Internal links open the correct page.
- Code blocks have the right language label.
- The page is readable on a narrow screen.

Do not commit generated folders such as `build/`, `.docusaurus/`, or `node_modules/`; they are excluded by `.gitignore`.
